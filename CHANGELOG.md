# Лабораторная 2

- `ConfigDict(from_attributes=True)` позволяет Pydantic получать значения полей из атрибутов объекта, например экземпляра ORM. `extra="forbid"` запрещает незаявленные поля, а `str_strip_whitespace=True` обрезает пробелы по краям строк.
- `Field` задаёт значение по умолчанию, ограничения и метаданные поля. Например, `min_length` и `max_length` проверяют длину, а `description` попадает в OpenAPI. Поле без значения по умолчанию обязательно.
- `Path` описывает параметр пути и задаёт правила его валидации. Положительный идентификатор проверяется условием `gt=0`. Ошибка проверки приводит к ответу 422.

# Лабораторная 3

- В `SettingsConfigDict` параметр `env_file` задаёт файл с настройками. Переменные окружения имеют приоритет. `extra="ignore"` позволяет использовать общий файл окружения с настройками, которые не входят в модель.
- `mapped_column` описывает столбец SQLAlchemy. Тип можно задать явно, например `String(32)`, или вывести из `Mapped[int]`. `primary_key` определяет первичный ключ, `unique` запрещает дубликаты, `nullable` задаёт допустимость NULL, а `ForeignKey` связывает строку с другой таблицей. `default` применяется SQLAlchemy, `server_default` задаётся на стороне БД.
- `echo` у `create_async_engine` включает вывод SQL и параметров для отладки. Этот же параметр есть у синхронного `create_engine`. Для проекта используется синхронная ORM с обычными обработчиками FastAPI.
- PostgreSQL реализует upsert через `INSERT ... ON CONFLICT DO UPDATE`. В PUT запись предварительно проверяется и блокируется на время транзакции, поэтому отсутствующий ID возвращает 404.

# Лабораторная 4

- При удалении строки refresh-токена PostgreSQL каскадно удаляет связанный access-токен. Уже выданный JWT может оставаться криптографически корректным до истечения срока, но приложение вернёт 401, поскольку дополнительно проверяет запись в БД.
- `class RegexEnum(str, Enum)` делает значения перечисления строкоподобными. Их можно передавать туда, где ожидается строка, например в проверку регулярного выражения. В этом проекте шаблон имени используется напрямую в `Field(pattern=...)`.
- Отдельный `TokenController` отвечает за выпуск, проверку и отзыв токенов. `AuthController` проверяет логин и пароль и передаёт выпуск токенов этому контроллеру. Это позволяет использовать правила работы с токенами при входе, ротации и выходе.
- OAuth2 Password Flow описывает получение токена при предъявлении имени и пароля приложением. Проект использует учебный вход через JSON и передаёт access-токен в заголовке Bearer. В Swagger токен вставляется в поле **Authorize**.
- bcrypt хранит хеш пароля с солью и настраиваемой вычислительной стоимостью. Для проверки используется `bcrypt.checkpw`. Для bcrypt вход ограничен 72 байтами после кодирования в UTF-8.
