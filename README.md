# База решений техподдержки

Учебный API на FastAPI. Проект посвящён заметкам с диагностикой и решениями технических проблем.

## Лабораторная 1

Запуск из корня проекта командой `docker compose up --build`. Интерфейс Swagger открывается по адресу http://localhost:8000/docs. Проверьте маршруты `GET /`, `GET /about` и `GET /health`. Последний возвращает `{"status":"ok"}`.

Чтобы собрать контейнер без Compose, выполните `docker build -t support-notes .` и `docker run --rm -p 127.0.0.1:8000:8000 support-notes`.

## Лабораторная 2

Пересоберите образ командой `docker compose up --build`. В Swagger создайте запись через `POST /posts` и сохраните полученный `id`.

```json
{
  "title": "Корпоративный VPN теряет соединение",
  "symptoms": "После выхода из сна страницы внутренней сети не открываются.",
  "solution": "Переподключить VPN и проверить доступ к внутреннему ресурсу."
}
```

Получите её через `GET /posts/{post_id}`, поменяйте решение через `PUT` и удалите через `DELETE`. Повторный `GET` даст 404. Укажите идентификатор 0, чтобы увидеть ошибку валидации 422. Данные этого этапа хранятся в памяти процесса.

## Лабораторная 3

`docker compose up --build` поднимает API и PostgreSQL. Перед запуском FastAPI контейнер применяет миграции Alembic. Swagger доступен на http://localhost:8000/docs.

Создайте пользователя через `POST /users` с JSON `{"username":"support_demo","display_name":"Дежурный инженер"}`. Проверьте получение списка и одной записи, изменение имени и удаление. Повторите CRUD для поста. Создайте ещё один пост, перезапустите Compose без удаления тома и проверьте, что пост сохранился.

## Лабораторная 4

Запустите `docker compose up --build`. Swagger доступен на http://localhost:8000/docs, каталог решений с поиском на http://localhost:8000/library.

1. Создайте новую учётную запись через `POST /users` с полями `username`, `display_name` и `password`. Например, `{"username":"demo_engineer","display_name":"Дежурный инженер","password":"demo-password-2026"}`.
2. Вызовите `POST /auth/login` с полями `username` и `password`. Скопируйте полученный `access_token` в окно **Authorize** и вызовите `GET /auth/verify`. В ответе будет ID пользователя.
3. Создайте пост через `POST /posts` и найдите его по слову «VPN» в каталоге. Чтение постов доступно всем, изменение требует действующей сессии. Пользователь может изменить или удалить свой профиль.
4. Передайте полученный `refresh_token` в `POST /auth/refresh`. Старая пара отзывается, а новая начинает действовать. Для последующих запросов заново заполните окно **Authorize**.
5. Передайте новый refresh-токен в `POST /auth/logout` и повторите `GET /auth/verify` с последним access-токеном. Ожидается 401.

Миграция сохраняет профили и посты из лабы 3. У старых профилей ещё нет пароля, поэтому для проверки входа создайте новую учётную запись. Без `JWT_SECRET` приложение генерирует ключ при старте, а перезапуск отзывает выданные ранее токены. Для стабильного ключа добавьте в локальный `.env` случайный `JWT_SECRET` длиной не менее 32 символов. Подписываются токены HS256. Access-токен действует 15 минут, refresh-токен — 7 дней.
